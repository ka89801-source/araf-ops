# أعراف — تجهيز المنصة الجديدة المستقلة

الهدف منصة عمليات فعلية بقاعدة بيانات مستقلة مستنسخة من الأصل وفاحص متصل بمساعد أعراف. يحتوي هذا الالتزام على نقل الأكواد المرفقة وفحصها كمرحلة عمل؛ استنساخ البيانات والربط الفعلي لم يُنفذا بعد، ويتطلبان اتصال Supabase. راجع [حالة التنفيذ](IMPLEMENTATION-STATUS.md).

## الإعدادات المستخرجة من الأصل

نُقلت إعدادات Supabase العامة وبريد الإدارة والإشعارات وعنوان المساعد إلى `server/source-platform.cjs` و`.env.example`. ملف `js/supabase.js` الأصلي موجود أيضًا كما كان. المفتاح الموجود في المصدر من نوع `sb_publishable_`؛ ليس مفتاح إدارة أو استنساخ.

الكود الأصلي يقرأ مفاتيح Supabase السرية وOpenAI وSerper وResend من متغيرات بيئة الاستضافة. لم تُعثر على قيم هذه الأسرار داخل ملفات GitHub التي فُحصت، لذلك لم تُملأ بقيم تخمينية.

`server/isolated-database.cjs` يجهّز إعداد اتصال الوجهة المستقلة، ويرفض عنوان قاعدة الإنتاج ومفتاحها العام، ويتوقف عند غياب إعدادات الوجهة. لم يُوصل هذا المكوّن بعمليات الواجهة بعد، ولا ينشئ أو يستنسخ قاعدة بيانات بنفسه. اجتياز فحص الإعداد لا يغني عن اختبار الاتصال الفعلي ومطابقة مشروع الوجهة.

```bash
node --test tests/isolated-database.test.cjs
```

## الملفات والمطابقة

- `index.html`: نسخة مطابقة بايتًا ببايت لملف `araf-ops.html` المرفق، تشمل التصميم والتفاعلات والأيقونات.
- `araf-ops-src/`: جميع ملفات المصدر المرفقة. التغيير الوحيد في المصدر هو `build.py` لجعل مسارات البناء مستقلة عن جهاز المؤلف وإضافة فحص المطابقة.
- ملفات `css/` و`js/` و`login.html` و`reset-password.html` القديمة محفوظة دون تعديل. لا تستدعيها واجهة المعاينة الجديدة؛ صفحات تسجيل الدخول القديمة تظل مرتبطة بالإنتاج، فلا تستخدمها لاختبار هذه المعاينة.
- لم تُضف أي إجراءات نشر أو تغييرات لقاعدة البيانات أو إعدادات الاستضافة.

## تشغيل المعاينة

من مجلد المستودع، شغّل:

```bash
python3 -m http.server 8080 --bind 127.0.0.1
```

ثم افتح `http://127.0.0.1:8080/`. لا تحتاج المعاينة إلى تسجيل دخول أو مفاتيح إنتاج.

إعادة بناء الصفحة أو التحقق منها:

```bash
python3 araf-ops-src/build.py
python3 araf-ops-src/build.py --check
```

يمكن تشغيل ملف البناء من أي مجلد، أو اختيار ملف إخراج آخر باستخدام `--output`.

## حدود النسخة المرفقة قبل الاعتماد

- الطلبات والموظفون والمنشآت والتذاكر بيانات تجريبية ضمن `data.js`؛ التاريخ المرجعي ثابت في 16 سبتمبر 2026.
- لا يوجد ربط بـ Supabase أو واجهات API الحالية، ولا تسجيل دخول فعلي أو صلاحيات خادمية. التعديلات على الطلبات محلية في الذاكرة وتعود إلى بيانات العرض عند إعادة التحميل.
- الثيم والجولة التعريفية والمراسلات وتقارير الفاحص تستخدم تخزين المتصفح المحلي؛ ليست مزامنة بين المستخدمين أو الأجهزة.
- إرسال الرسائل والردود وإشعاراتها محاكاة محلية؛ لا تُرسل إلى الفريق أو العملاء.
- الفاحص القانوني يعتمد على `window.claude.use('sample')`. هذه القدرة غير متاحة في الاستضافة العادية، فتظهر حالة عدم توفر الخدمة. لم يُضف مزود ذكاء اصطناعي أو مفتاح سري.
- بعض الإجراءات تعرض إشعارات توضيحية فقط (`stub`)، ولا تنفذ خدمة خلفية.

للاعتماد الفعلي لاحقًا يلزم ربط البيانات والمصادقة والصلاحيات والحفظ والخدمات الخارجية، واختبارها في بيئة اختبار منفصلة. لا تغيّر برنش الإنتاج أو نطاقه إلى هذا البرنش قبل اكتمال ذلك وموافقة صاحب المشروع.
